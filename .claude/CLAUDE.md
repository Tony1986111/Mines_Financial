# CLAUDE.md — mines_financial

## 变更必须留痕

本项目有两份长期维护的记录文档，位于
`zzz_helper/upgrade_debug_md/`：

| 文档 | 什么时候写 |
|---|---|
| `UPGRADE.md` | 新增、修改、删除任何功能时；调整任何架构时 |
| `DEBUG.md` | 每次 debug 时；每次解决项目中遇到的问题时 |

**要求：改完代码就补记录，在同一次任务内完成，不要留到下次。**

新条目加在文件顶部（最新在最上面），并遵循各文件开头写明的格式。

补充说明：

- 排查过程中**发现但未修**的问题也要记入 `DEBUG.md`，标注状态为
  `未解决` 或 `已知限制`，不要因为没动手就不记。
- 一次改动同时涉及功能变更和问题修复时，两份文档都写，
  各自只写自己那一面，用日期互相对照，不要复制粘贴同一段内容。
- 记录要包含**实测数字和定位过程**，不只是结论。
  "把 K 改成 20" 没有价值，"权重比 1.22 大于名次跨度比 1.11，
  导致 BM25 独有文档恒被排在截断线外" 才有价值。
- 纯粹的格式化、lint 修复、注释错别字不必记录。
